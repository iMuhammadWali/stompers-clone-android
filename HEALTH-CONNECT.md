# Personal race / Health Connect v1

The Home race shows only the current device user's steps for the current local day,
with their saved character and companion. Connect explicitly requests **read Steps**
access. No health writes, background/history permissions, server uploads or competitor
step data are implemented. Character choices remain account-scoped local settings.

The service uses Health Connect's `aggregateRecord(Steps)` and its `COUNT_TOTAL`, rather
than adding raw records from different source apps. Time range: local midnight to now.
An empty aggregate is zero; unavailable/denied/error states are not represented as zero.
The screen refreshes on focus, on foreground return, every minute while focused, and
on Refresh steps. A new day clears the previous day's displayed total while refreshing.

## On a phone

1. Install the APK, open Stride, and choose **Explore demo** if the backend is unconfigured.
2. Open the Home race and tap **Connect Health Connect**. Allow read access to Steps.
3. In your fitness app (for example Samsung Health or Google Fit), enable sharing Steps
   with Health Connect. Stride reads the shared store; it does not collect steps itself.
4. Return to Stride and tap **Refresh steps**. Your character is the one saved by the creator.
5. If access was denied repeatedly, use **Health Connect settings** to enable Steps access.

Health Connect is built into Android 14+; earlier supported devices may need the Health
Connect app from Google Play. The provider requires Android 9 or later and a secure lock.
Web and Expo Go cannot read Health Connect; use this standalone native build.

## Testing

`npm test` tests a fake native bridge: 6,142 steps, zero/no data, explicit permission,
denial/revocation, provider update/unavailability, failed/invalid reads, and local midnight
in Asia/Karachi. The fake bridge exists only in tests; no synthetic counts or records are
injected into the phone's health store. UI tests verify the personal counter, saved avatar,
connect action, empty state, and honest unsupported-web behavior.

Native prebuild checks verify READ_STEPS and both permission-usage/rationale routes to
HealthPermissionsActivity. This is generated by `plugins/withHealthPrivacy.js`; native
folders are generated, not maintained manually. The library's Expo autolinking registers
its permission delegate. Its stock manifest plugin is replaced by the app's dedicated
privacy activity so the system privacy link shows the actual step-use explanation.

Physical-device permission and actual health-app sync require testing on the user's phone.
The APK build is separate from JS exports and mocked integration tests.

## Rebuilding

Use JDK 17+, Android SDK 36 / Build Tools 36.0.0, NDK 27.1.12297006 and CMake 3.22.1.
Run `npm ci`, `npx expo prebuild --platform android --no-install`, then
`cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a`.
This internal test build uses the Expo template's test signing key; it is not a Play Store
production release. EAS preview is also configured for APK output.
