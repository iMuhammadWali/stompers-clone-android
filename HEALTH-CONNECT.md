# Daily race / Health Connect

Home shows the selected source’s steps and saved character. Accepted friends appear in the daily race with their synced totals, character and last-sync time. Accounts require character and username setup. Daily totals are uploaded while Home is open; raw sensor measurements are not uploaded. Only read Steps permission is requested; no health writes or background/history Health Connect permissions are used.

Health Connect uses aggregateRecord(Steps) and COUNT_TOTAL, never a sum of overlapping raw source records. The time window is midnight Asia/Karachi to now for every player. An empty aggregate is zero; unavailable, denied and error states remain unknown. The local reading refreshes on focus, foreground return, once per minute and manual refresh. Phone-source readings refresh every five seconds; server race sync runs every fifteen seconds while foregrounded. One selected source replaces the daily total; sources are never added together.

## On a phone

1. Install the APK, open Stride, and choose **Explore demo** if the backend is unconfigured.
2. Open the Home race and tap **Connect Health Connect**. Allow read access to Steps.
3. In your fitness app (for example Samsung Health or Google Fit), enable sharing Steps
   with Health Connect. In Health Connect mode Stride reads the shared store. Phone-sensor mode is a separate optional source described below.
4. Return to Stride and tap **Refresh steps**. Your character is the one saved by the creator.
5. If access was denied repeatedly, use **Health Connect settings** to enable Steps access.

Health Connect is built into Android 14+; earlier supported devices may need the Health
Connect app from Google Play. The provider requires Android 9 or later and a secure lock.
Web and Expo Go cannot read Health Connect; use this standalone native build.

## Testing

`npm test` tests a fake native bridge: 6,142 steps, zero/no data, explicit permission,
denial/revocation, provider update/unavailability, failed/invalid reads, and midnight
in Asia/Karachi. The fake bridge exists only in tests; no synthetic counts or records are
injected into the phone's health store. UI tests verify the personal counter, saved avatar,
connect action, empty state, and honest unsupported-web behavior.

Native prebuild checks verify READ_STEPS and both permission-usage/rationale routes to
HealthPermissionsActivity. This is generated by `plugins/withHealthPrivacy.js`; native
folders are generated, not maintained manually. The library's Expo autolinking registers
its permission delegate. Its stock manifest plugin is replaced by the app's dedicated
privacy activity so the system privacy link shows the actual step-use explanation.

Physical-device permission and actual health-app sync require testing on the user's phone.
The APK build is separate from JS exports and mocked integration tests.

## Rebuilding

Use JDK 17+, Android API 37 (SDK package platforms;android-37.0) / Build Tools 37.0.0, NDK 27.1.12297006 and CMake 3.22.1.
Run `npm ci`, `npx expo prebuild --platform android --no-install`, then
`cd android && ./gradlew assembleRelease --max-workers=1 -Pkotlin.compiler.execution.strategy=in-process -PreactNativeArchitectures=arm64-v8a`.
The prebuild entry-point plugin validates generated app classes and neutralizes stale Expo template copies; do not edit generated Android sources manually.
This internal test build uses the Expo template's test signing key; it is not a Play Store
production release. EAS preview is also configured for APK output.

## Race screen v1.0.1

The outlined daily counter sits above an open, responsive race stage. Connection,
installation, empty-source and read-error explanations appear before the track,
so connecting steps does not require scrolling past the character. The character
marker follows today's aggregate toward a clearly labeled 10,000-step personal target.
The marker stops at the flag after the target; the main count retains every extra step.
Tap the Health Connect sync line for details and step-access settings. This screen does
not display sampled friends or fabricate weekly history, rankings, rewards or steps.

## Phone sensor fallback v1.1.0

Health Connect is optional for this mode. Open the race menu and select **Use phone step sensor** (or **Use phone tracking instead** above the race). Grant **Physical activity**, and allow notifications so the Stop control is easy to reach. Carry the phone and walk; the displayed count refreshes every five seconds while Home is open. Hardware counter delivery itself may lag by ten seconds.

The native service continues counting with the screen off where the device supports it. It prefers a step counter, then a step detector. With neither sensor, a separate experimental accelerometer opt-in appears. The estimate has known false positives and missed short/slow bouts, and uses more battery. No synthetic steps are injected.

Counts begin at activation. Stop keeps the recorded total visible and marks it paused. Resume excludes the stopped interval. Reboot/update recovery is attempted only if you left tracking enabled and permission remains granted; open the app to Resume if the system prevents recovery. Force-stop and vendor battery restrictions can interrupt tracking. Local-day/zone boundaries use conservative accounting and may exclude an ambiguous interval.

Choose **Use Health Connect instead** to switch sources; totals are replaced, never added. Phone mode does not read or write Health Connect. No location or body-sensor access is requested. Android backup is disabled for app data.

Research, implementation details, replay results and the outstanding physical-validation protocol: [STEP-TRACKING-RESEARCH.md](STEP-TRACKING-RESEARCH.md). Run `scripts/test-phone-core.sh` with a JDK on PATH to test the actual native accounting/detector core.
